# Deployment records

## Platform chain configuration (API)

`chains.json` is the platform chain configuration. Each enabled chain must provide
at least two distinct RPC URLs and has a matching `<chainId>.json` manifest.

```json
{
  "chains": [
    {
      "chainId": 11155111,
      "name": "Ethereum Sepolia",
      "isTestnet": true,
      "confirmations": 3,
      "explorerUrl": "https://sepolia.etherscan.io",
      "rpcUrls": ["https://rpc-one.example", "https://rpc-two.example"],
      "enabled": true
    }
  ]
}
```

The API reads `<chainId>.json` manifests for enabled chains using this shape:

```json
{
  "chainId": 11155111,
  "deployments": {
    "TREASURY_MODULE_IMPLEMENTATION": {
      "address": "0x1111111111111111111111111111111111111111",
      "codeHash": "0x1111111111111111111111111111111111111111111111111111111111111111",
      "version": "1.0.0"
    }
  }
}
```

The module implementation is mandatory. Every deployment address and code hash
must be a non-zero 20-byte and 32-byte hexadecimal value, respectively. Never
place private keys, authenticated RPC URLs, or other credentials in these files.

RPC URLs are stored in the database as written here, so provider API keys and
basic-auth credentials must be `${ENV_VAR}` placeholders that consumers expand
at use time, for example
`https://eth-sepolia.g.alchemy.com/v2/${ALCHEMY_API_KEY}`. Literal userinfo or
query values are rejected; a key in the path cannot be detected and must be a
placeholder by convention.

Chains removed from `chains.json` are disabled (not deleted) on the next API
start.

The API reads these paths from `TP_PLATFORM_CHAIN_CONFIG_PATH` and
`TP_DEPLOYMENTS_DIR`; both default to this directory, resolved from the
repository root rather than the working directory.

## Contract deployment records

`31337.json` is generated by the local Anvil script and records real local
addresses and code hashes. Keep that private local output out of source control.

`11155111.json` records canonical Sepolia infrastructure and the expected schema
UID. Its status remains `configured_only` until a user broadcasts the deploy and
schema-registration scripts. Null fields are deliberately un-deployed addresses,
not predicted or fabricated records. A successful Sepolia broadcast replaces the
manifest with actual addresses and code hashes after `infra/scripts/publish_manifest.py`
verifies mined RPC state. Forge scripts only write ignored prediction artifacts
under `deployments/predictions/`; simulation cannot overwrite either published
manifest. The local deployment wrappers run verification and publication after
successful broadcast. Schema-only publication preserves the existing deployment
metadata and stores its UID as a scalar hex string.

The contracts are gated to Anvil (`31337`) and Sepolia (`11155111`). The Aave pool,
USDC and USDC aToken are from the Aave address book commit recorded in the manifest.
`make config-check` compares the live RPC chain id, token decimals, reserve mapping,
and aToken identity against that reviewed manifest; set `SEPOLIA_RPC_URL` or
`ETH_RPC_URL` before running it locally or before a demo. The EAS
Registry and EAS addresses follow the EAS Sepolia deployment at its pinned source
revision. Live Etherscan verification and a sample easscan attestation need the
user's testnet broadcast key, RPC and explorer API key.

Canonical Safe 1.4.1 infrastructure is pinned to the recorded safe-deployments
revision; Anvil alone deploys local copies. `easAttester` must identify a dedicated
receipt signer before public use. The CLI refuses an unconfigured or different
signer; receipt consumers must check that identity, not only the public schema.
The manifest records the USDC supply-cap blocker at the evidence block and the
separate historical USDC success pin. See [deployment and receipt operations](../contracts/docs/DEPLOYMENT.md)
for mandate expiry, finality and persistent retry journals.

> shape share the `<chainId>.json` file name. `chains.json` is empty today, so
> the API does not read them yet; reconcile the two shapes before enabling
> Sepolia in `chains.json`.
