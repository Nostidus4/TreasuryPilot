# Deployment records

`31337.json` is generated by the local Anvil script and records real local
addresses and code hashes. Keep that private local output out of source control.

`11155111.json` records canonical Sepolia infrastructure and the expected schema
UID. Its status remains `configured_only` until a user broadcasts the deploy and
schema-registration scripts. Null fields are deliberately un-deployed addresses,
not predicted or fabricated records. A successful Sepolia broadcast replaces the
manifest with actual addresses and code hashes after `infra/scripts/publish_manifest.py`
verifies mined RPC state. Forge scripts only write ignored prediction artifacts
under `deployments/predictions/`; simulation cannot overwrite either published
manifest. The local deployment wrappers run verification and publication after
successful broadcast. Schema-only publication preserves the existing deployment
metadata and stores its UID as a scalar hex string.

The contracts are gated to Anvil (`31337`) and Sepolia (`11155111`). The Aave pool
and USDC are from the Aave address book commit recorded in the manifest. The EAS
Registry and EAS addresses follow the EAS Sepolia deployment at its pinned source
revision. Live Etherscan verification and a sample easscan attestation need the
user's testnet broadcast key, RPC and explorer API key.

Canonical Safe 1.4.1 infrastructure is pinned to the recorded safe-deployments
revision; Anvil alone deploys local copies. `easAttester` must identify a dedicated
receipt signer before public use. The CLI refuses an unconfigured or different
signer; receipt consumers must check that identity, not only the public schema.
The manifest records the USDC supply-cap blocker at the evidence block and the
separate historical USDC success pin. See [deployment and receipt operations](../contracts/docs/DEPLOYMENT.md)
for mandate expiry, finality and persistent retry journals.
